    ¿Por qué aprender Claude Code?

    Claude Code es un asistente de programación que se integra directamente en tu terminal y flujo de trabajo, permitiéndote escribir, depurar y entender código más rápido.

    Aprender a usarlo te ayuda a automatizar tareas repetitivas, explorar bases de código grandes con mayor facilidad y aumentar tu productividad como desarrollador, sin importar tu nivel de experiencia.

    Qué puede hacer

    Entender código

    Explica proyectos desconocidos, busca dónde vive cada cosa.

    Escribir y editar

    Crea archivos, modifica varios a la vez, refactoriza.

    Depurar

    Lee errores, ejecuta tests, propone y aplica correcciones.

    Automatizar git

    Commits, ramas y pull requests con mensajes descriptivos.

    Cómo usar este curso

    Avanza con Siguiente / Atrás o las flechas ← → del teclado. El botón de menú (arriba a la izquierda) abre el índice para saltar a cualquier capítulo.

    Instalación y primer arranque

    Un comando para instalar, otro para iniciar. Necesitas una cuenta de Claude (Pro, Max, Team, Enterprise) o una cuenta de API en Anthropic Console.

    1. Instalar

    irm https://claude.ai/install.ps1 | iex

    Ejecútalo en PowerShell. En Windows conviene tener Git for Windows instalado.

    curl -fsSL https://claude.ai/install.sh | bash
    npm install -g @anthropic-ai/claude-code

    Requiere Node.js 18 o superior.

    2. Verificar

    claude --version
claude doctor

    3. Iniciar en tu proyecto

    cd ruta/a/mi-proyecto
claude

    La primera vez te pedirá iniciar sesión (o usa /login más tarde). Después verás un cuadro de texto: ya puedes escribir.

    Consejo

    Siempre inicia claude desde la carpeta raíz del proyecto: esa es la carpeta que Claude ve y puede modificar.

    Tu primera sesión

    Conversas en lenguaje natural. Claude lee, propone cambios y tú apruebas.

    $ claude > explícame la estructura de este proyecto ● Leyendo package.json, src/… Es una API en Node con Express. src/routes define los endpoints… > agrega validación de email en @src/routes/users.js ● Edit(src/routes/users.js) + if (!isValidEmail(email)) return res.status(400)… ¿Aplicar cambio? [Sí] [Sí, siempre] [No]

    El ciclo básico

    1. Pides algo en un prompt.
    2. Claude explora: lee archivos, busca, ejecuta comandos.
    3. Propone ediciones o comandos y espera tu permiso.
    4. Verifica (tests, build) y te informa.

    Prompts que funcionan

    • Específicos: "agrega un test para el caso de email vacío en users.test.js" mejor que "mejora los tests".
    • Con contexto: menciona archivos con @ruta/archivo.
    • Con criterio de éxito: "…y confirma que npm test pasa".
    • Por pasos: primero investigar, luego implementar.
    Revisa siempre

    Lee los cambios propuestos antes de aceptarlos. Claude puede equivocarse; tú decides qué se aplica. Con Esc lo interrumpes en cualquier momento.

    Desde la terminal

    claude                    # sesión interactiva
claude "explica este repo"  # inicia con un prompt
claude -p "resume README.md"  # una respuesta y termina (scripts)
claude -c                 # continúa la última conversación
claude -r                 # elige una conversación para retomar

    Permisos y modo plan

    Claude pide permiso antes de editar archivos o ejecutar comandos. Tú controlas cuánta autonomía le das. Cambia de modo con Shift+Tab.

    ModoComportamiento
    NormalPregunta antes de editar o ejecutar comandos.
    Aceptar edicionesEdita archivos sin preguntar; los comandos siguen pidiendo permiso.
    PlanSolo lee y propone un plan. No modifica nada hasta que lo apruebes.
    Sin permisos--dangerously-skip-permissions: sin preguntas.
    Cuidado

    Usa el modo sin permisos únicamente en entornos aislados (contenedor, máquina virtual) y nunca con datos que no puedas perder.

    Cuándo usar modo plan

    Para tareas grandes o ambiguas: Claude investiga y presenta un plan; lo revisas, corriges y solo entonces se ejecuta. Reduce sorpresas.

    Reglas permanentes

    Evita aprobar lo mismo cien veces. Define reglas en .claude/settings.json (o con /permissions):

    {
  "permissions": {
    "allow": ["Bash(npm run test:*)", "Bash(git status)"],
    "deny": ["Read(./.env)"]
  }
}

    CLAUDE.md y memoria

    Claude no recuerda conversaciones pasadas por defecto. CLAUDE.md es el archivo que lee automáticamente al iniciar para conocer tu proyecto y tus preferencias.

    Dónde puede vivir

    UbicaciónAlcance
    ~/.claude/CLAUDE.mdGlobal: todas tus sesiones, todos los proyectos.
    ./CLAUDE.mdProyecto: raíz del repo; se comparte con el equipo.
    subcarpeta/CLAUDE.mdSe carga al trabajar en esa carpeta.

    Crearlo

    /init

    Claude analiza el proyecto y genera un borrador. Edítalo con /memory o a mano.

    Ejemplo mínimo

    # Mi proyecto
API REST en Node 20 + Express.

## Comandos
- Tests: npm test
- Lint: npm run lint

## Reglas
- Responde siempre en español.
- Usa async/await, nunca callbacks.
- No modifiques archivos en /migrations.
    Consejo

    Que sea corto y concreto: comandos, convenciones y "no hagas X". Todo lo que escribas consume contexto en cada sesión.

    Gestionar el contexto

    El contexto es todo lo que Claude "tiene en mente": conversación, archivos leídos, salidas de comandos. Es limitado; cuando se llena, la calidad baja.

    /context

    Mide cuánto has usado y en qué.

    /compact

    Resume lo hecho y libera espacio, conservando lo esencial.

    /clear

    Empieza limpio. Úsalo al cambiar de tarea.

    /resume

    Vuelve a una conversación anterior.

    Buenas prácticas

    • Una tarea por sesión. Al terminar, /clear.
    • Guía el resumen: /compact conserva las decisiones de diseño y la lista de archivos tocados.
    • Menciona solo los archivos necesarios con @, no carpetas enormes.
    • Lo que debe persistir siempre va a CLAUDE.md, no a la conversación.

    Skills, agentes y hooks

    Tres formas de extender a Claude Code con tus propias reglas y flujos.

    Skills

    Instrucciones empaquetadas para un tipo de tarea. Claude las carga cuando la descripción coincide con lo que pides, o las invocas con /nombre.

    # .claude/skills/revisar-codigo/SKILL.md
---
name: revisar-codigo
description: Revisa cambios buscando bugs y problemas de estilo.
---
1. Lee el diff actual.
2. Lista los problemas por severidad.
3. Propón correcciones concretas.

    Agentes (subagentes)

    Claude especializado con su propio contexto y herramientas. Delega investigaciones largas sin ensuciar tu conversación principal. Créalos con /agents o un archivo:

    # .claude/agents/revisor.md
---
name: revisor
description: Revisa código sin modificarlo.
tools: Read, Grep, Glob
---
Eres un revisor estricto. Solo reporta hallazgos.

    Hooks

    Comandos de shell que se ejecutan automáticamente ante eventos (antes/después de usar una herramienta, al terminar, etc.). Se configuran en settings.json:

    {
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npx prettier --write ." }]
      }
    ]
  }
}

    Ese ejemplo formatea el código cada vez que Claude edita un archivo.

    Conectar herramientas con MCP

    El Model Context Protocol conecta Claude Code con servicios externos: bases de datos, GitHub, Slack, Jira, navegadores, etc. Cada servidor añade herramientas nuevas.

    Añadir un servidor

    claude mcp add --transport http mi-servidor <URL-del-servidor>
claude mcp list
claude mcp remove mi-servidor

    Dentro de una sesión, /mcp muestra el estado y permite autenticarse.

    Alcance

    • Local: solo tú, solo este proyecto.
    • Proyecto: archivo .mcp.json en el repo; lo comparte el equipo.
    • Usuario: disponible en todos tus proyectos.
    Seguridad

    Un servidor MCP puede leer y actuar en tu nombre. Conecta solo servidores de fuentes en las que confíes.

    Flujo de trabajo con git

    Claude Code trabaja mejor sobre un repositorio git: cada cambio queda registrado y es reversible.

    Flujo recomendado

    1. Crea una rama: git switch -c mi-funcionalidad.
    2. Pide la tarea (usa modo plan si es grande).
    3. Revisa con git diff y ejecuta los tests.
    4. Pide: "haz commit con un mensaje descriptivo".
    5. Si tienes la CLI gh: "abre un pull request".

    Deshacer

    • Esc Esc o /rewind: vuelve a un punto anterior de la sesión y restaura archivos.
    • git restore <archivo> o git revert: deshace en el repositorio.
    Consejo

    Haz commit antes de una tarea grande. Es tu red de seguridad. Claude solo hace commit, push o acciones destructivas si se lo pides.

    Glosario

    Términos usados al trabajar con Claude Code en la terminal.

    TérminoSignificado
    PromptInstrucción o mensaje que le escribes a Claude Code para pedirle una tarea.
    Slash commandComando especial que empieza con "/" (por ejemplo /help, /login) para ejecutar acciones predefinidas.
    Agente (Agent)Subproceso de Claude que se encarga de una tarea específica de forma autónoma, con sus propias herramientas.
    Herramienta (Tool)Función que Claude puede invocar para interactuar con el sistema, como leer archivos, editar código o ejecutar comandos.
    SkillConjunto empaquetado de instrucciones para realizar un tipo de tarea concreto (por ejemplo revisión de código).
    HookComando de shell configurado para ejecutarse automáticamente en respuesta a eventos, como el uso de una herramienta.
    MCP (Model Context Protocol)Protocolo que permite conectar Claude Code con servidores externos que exponen herramientas adicionales.
    Contexto (Context window)Cantidad de conversación e información que Claude puede "recordar" y procesar en un momento dado.
    Memoria (Memory)Sistema persistente donde Claude guarda información relevante del usuario o proyecto entre conversaciones.
    WorkflowScript que orquesta múltiples agentes de forma determinista para tareas complejas en varias etapas.
    Repositorio (Repo)Carpeta de proyecto controlada por git, sobre la cual Claude Code puede operar y hacer commits.
    CommitRegistro de cambios guardado en el historial de git, generalmente con un mensaje descriptivo.
    Branch (Rama)Línea independiente de desarrollo dentro de un repositorio git.
    CLAUDE.mdArchivo de configuración con instrucciones y preferencias que Claude Code lee automáticamente en cada proyecto.
    ArtifactPágina web (HTML o Markdown) publicada por Claude Code que se puede compartir con otras personas.

    Reglas de oro

    1. Sé específico y da un criterio de éxito verificable.
